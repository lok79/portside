## 正文草稿（首楼，可直接粘贴）

<!-- GIF：上传 docs/screenshots/portside-demo.gif 为首楼动图 -->

各位好，分享一个我最近做完 v1 的开源小工具：**Portside（服务码头）**。

**痛点**

日常开发里服务都活在后台：`nohup java -jar ...`、`npm run dev`、各种脚本一把梭。它们没有前台——过两天就忘了哪个端口是谁、哪个还活着、哪个挂了半宿没人知道，全靠 `lsof -i :8080` 逐个摸。我给它们修了个码头。

**它做什么**

- **自动发现**：周期扫描监听端口 ↔ 进程映射（lsof 主路径 + netstat 交叉核对），认出 Java 后端（jar 文件名清洗版本尾巴）和前端 dev server（vite/next/vue-cli）；认不出的显示"未知 + 端口"，不猜。
- **四区列表**：我的服务 / 后端 / 前端 / 其他；不相干进程按名字聚成一行（"QQ（35 个端口）"默认折叠），"隐藏其他"一键收起。
- **收编**：外部起的服务补一条启动命令就升级"托管"，停止/重启/日志立刻解锁；危险动作二次确认。
- **日志流**：托管服务直写落盘日志实时跟随；外部服务尽力找（nohup.out、logs/ 兜底），真没有就明说"未发现日志文件"，不装死。
- **图标警示**：收编过的服务挂了，菜单栏图标变红色警示三角——不开面板也知道。
- **刷新三档**：实时 5s / 均衡（活动 5s、空闲 30s，默认）/ 低资源（30s/120s），底栏即切。

**几个刻意的设计**

- 服务的第一次启动永远由你自己做，Portside 只负责发现和后续管理——它不想替你决定跑什么。
- 退出不清场：Portside 退出，你的服务照常跑；重开自动按"端口 + 启动命令"认领回托管态。
- 原生 SwiftUI，零第三方依赖、零网络、零遥测。

**诚实自曝**

- 未公证（ad-hoc 签名），首次打开 macOS 拦一次，Finder 右键打开或 `xattr -cr /Applications/Portside.app` 过一次就好；
- 仅 macOS 14+ / Apple Silicon；
- 外部服务的日志是尽力发现：stdout 在进程启动那刻就流向了别处，只能找落盘文件。

**下载**

- GitHub（含源码）：https://github.com/lok79/portside
- Releases（免构建）：https://github.com/lok79/portside/releases/latest
