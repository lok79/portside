# 托管服务与 Portside 生命周期解耦

Portside 只是菜单栏里的管家，而微服务是长跑选手——用户更新/重启 Portside 不应殃及服务。决定：托管服务（Portside 启动的服务）与 Portside 生命周期解耦，退出不清场；托管服务的标准输出经 PTY 同步落盘为日志文件（日志 UI 与外部服务统一为 tail 文件）；Portside 重开时按服务定义（端口 + 启动命令匹配）自动「认领」回托管态。

status: accepted

## Considered Options

- **B 退出时弹窗询问（停止/保持）**：拒绝——每次退出都打扰，且"保持运行"分支仍要实现 A 的全部逻辑。
- **C 退出即全停托管服务**：拒绝——用户只是想重启一下菜单栏应用，三个微服务就被带走、前端立刻 502；"下班全清"应是显式按钮而非退出副作用。

## Consequences

- 日志管道全产品统一：托管与外部服务的日志栏都是"发现文件 → tail"，托管服务仅多了"文件由 Portside 落盘"这一环。
- 必须实现认领匹配逻辑：以持久化的服务定义为依据，按端口 + 启动命令匹配运行中实例；匹配不上的落回外部态，绝不误认。
- 若未来把解耦改成"退出即停"，PTY/落盘/认领三处都要返工——本 ADR 即为此立此存照。
