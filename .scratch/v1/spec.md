## 一句话定位

macOS 菜单栏应用：自动发现本机正在运行的开发服务（Java 后端 / 前端 dev server），随手看名称、端口、存活状态，管启动/停止/重启、浏览器打开、查看日志。让"跑在后台的服务"第一次有前台感知。

## 用户故事

1. 小李起了三个 Spring Boot 微服务加一个 vite 前端，半天后想确认 user-service 还活着——点菜单栏图标，一眼看到 ● user-service :8081 正常、○ order-service 已挂，全程没开终端。
2. 前端代理报 502，点 order-service 那一行，同窗切到日志视图看到 OOM 堆栈，点「重启」，菜单栏图标十秒后恢复全绿。
3. 要给同事演示本地接口，点服务行的「打开」，浏览器直达 `http://localhost:8081`。
4. 早上 nohup 起的 gateway 在列表里标着「外部」，能看能探活；点「收编」确认一下预填的启动命令，停止/重启/日志立刻解锁。
5. 下午更新 Portside 退出重开——服务照跑，重开后自动认领，user-service 还是托管态、日志完整接上。

## 形态

- 常规独立窗口 + 菜单栏双入口（D-004 修正注记 2026-10-24）：启动即显示主窗——常规独立窗口（标题「Portside · 服务码头」，约 620px 紧凑面板原样），Dock 出现锚形图标；关闭主窗 app 不退出，点 Dock 或菜单栏图标重新打开/聚焦主窗
- NSStatusItem 菜单栏锚形图标常驻，汇总态直接上图标（全绿 / 有服务挂了变色），不开窗也能感知；点击弹出菜单（打开主窗口 / 退出 Portside）；**列表与日志同窗切换，无独立浮动小窗**
- 界面模型（拷问时确认用）：`.zcode/v2/visualizations/…/portside-form-factor.html` 形态 A 变体（多屏/自动隐藏菜单栏的发现性缺陷实证与修正如实记录在 D-004 修正注记）

## 功能需求（P0）

### 1. 扫描与识别
- 周期枚举本机监听端口 ↔ 进程映射（系统接口，非暴力连端口），退避策略：活动期 ~5s、空闲退到 ~30s
- 识别类型：Java（jar 文件名清洗版本尾巴 / 主类，辅助 `jps -l`）、前端 dev server（vite/next/vue-cli 进程特征）、其余为未知
- 识别器接口化：Java/前端只是首批，后续技术栈按同一接口扩展（D-005），引擎不写死单一栈假设
- 识别不出显示「未知 + 端口」，不猜名字
- 刷新模式三档可配：Realtime / Balanced（默认）/ Low Resource——回应"lsof 每 5 秒太重"的经典质疑，服务低占用硬约束
- macOS 15+ 收紧 lsof 对 root 套接字的访问（Pier 踩过的坑）：扫描降级策略（组合数据源）+ 列表可能不完整时 UI 明示，进 v1 测试矩阵
- 显示名优先级：**用户别名 > 清洗后的识别名 > 未知 + 端口**；同名多实例并存（同名不同端口各占一行，不合并）

### 2. 分区（四区）
- **我的服务**：有服务定义的（收编产生），含已停止实例，永远展开
- **后端**：识别为 Java、尚未收编的
- **前端**：识别为 dev server 的
- **其他**：未识别进程按进程名聚合成单行（如「QQ（5 个端口）」），默认折叠；「隐藏其他」开关，隐藏后仍不静默丢弃（展开即可见）
- 服务一旦收编，从后端/前端移入「我的服务」

### 3. 服务定义与收编
- 服务定义 = 持久配置（显示名、启动命令、端口），**只由收编产生，v1 没有手动登记新服务的入口**——服务的第一次启动永远由用户自己在终端做，Portside 负责发现
- 收编弹窗三字段全部预填：名称（清洗识别名）、启动命令（该进程当前 argv 原样——它怎么起的就怎么还给你）、端口（当前端口）；可改，保存即生成定义
- 保存后该服务立即从外部转托管：停止/重启/日志解锁；定义持久化，重启电脑后仍有效

### 4. 托管操作与生命周期
- 启动/停止/重启：托管服务全量可用；外部服务灰置 + 「收编」入口
- 危险动作确认：停止/重启前显示占用者解释并二次确认（抄 TidyPorts 的分级设计，不学 devglow 的自动杀占用者）
- 进程组处理：停止/重启对整组发信号（Java 会 fork 子进程），杀干净不留孤儿
- 由 Portside 启动的服务输出**直写**日志文件（落盘语义见 adr/0001；真 PTY 留给 v1.x 交互 stdin 场景）
- **退出不清场**（adr/0001）：Portside 退出时托管服务照常运行；重开后按定义（端口 + 启动命令）自动「认领」回托管态，匹配不上的落回外部态，不误认

### 5. 浏览器打开
- 默认 `http://localhost:{port}`，每个服务可自定义路径前缀（如 `/swagger-ui`）

### 6. 日志（托管与外部统一管道：发现文件 → tail）
- 托管服务：tail 自己的落盘日志（PTY 落盘那一份）
- 外部服务：①主路径——lsof 查该进程**以写/追加模式打开**的 .log/.out 文件（进程正在写的文件，命中即正确）；②兜底——工作目录下 nohup.out、logs/、log/ 取最近修改的一个；③都失败——明示「外部启动，未发现日志文件」，不装死
- 命中后 tail 末尾 500 行并跟随

### 7. 低资源硬约束
- 常驻内存 < 80MB（验收硬指标），空闲 CPU 趋近 0
- 扫描退避 + 短超时 TCP 探活，不做常驻网络轰炸

## 非目标（v1 明确不做）

- 手动登记新服务入口（见 3，用户自己的决定：没起过的服务他自己起）
- 性能监控大盘（CPU/内存曲线）
- 远程服务器、Docker 容器
- 非 macOS 平台
- App Store 分发（沙箱与产品本质冲突，见 D-004 No-gos）
- 团队协作/云同步
- v1.x 候选池（调研后排序，进 v1 前需重新拍板）：agent 归因（每行显示谁/哪个 agent 启动的）、MCP server（先只读：列服务/查端口/看日志）、分组整组启停、挂掉通知、健康历史、包装命令的兜底停止（进程树归因——收编 `npm run dev` 类包装命令后实际监听者是 node/vite，端口兜底停止因杀前命令校验必 mismatch 拒杀，v1 记为已知限制）、未知端口的可见性（2026-10-24 实机案例：Python http.server 起的 8080 被「隐藏其他」藏住，用户报"服务不见了"——候选：未知新端口轻提示 / 静态文件服务器识别器（http.server、http-server、serve）/ 其他区新端口计数角标）

## 技术要点

- Swift + SwiftUI + AppKit（NSStatusItem）；Swift Concurrency
- 端口↔进程：libproc（proc_pidinfo）优先，`lsof -i -P -n`（-P -n 必带，否则 DNS/端口名反解慢到不可用）与 netstat 组合兜底；Java 识别辅以 `jps -l`（v1 实现取舍见 adr/0002）
- 进程树：Portside 启动的服务挂独立进程组，停止/重启对整组发信号
- 进程管理：`Process` API + 独立进程组；托管服务输出直写日志文件（`~/.portside/logs/<name>.log` 或应用容器内，实现时定；真 PTY 留给 v1.x），日志 UI = tail 文件
- 定义持久化：本地配置文件（随应用数据目录）
- 非沙箱 + Hardened Runtime + 公证；分发 dmg 直发 / brew cask

## 验收标准

1. 起 2 个 Java 服务（含 1 个 fat jar）+ 1 个 vite dev server，5 秒内全部出现、端口正确、分区正确
2. `kill -9` 一个后端，10 秒内菜单栏图标变「有挂」状态
3. 收编一个 nohup 起的外部服务：弹窗三字段预填正确，保存后停止/重启/日志立即可用，服务行移入「我的服务」
4. 托管服务全量操作可用；**重启 Portside，托管服务不死、自动认领回托管态、日志完整**
5. 外部日志三场景：nohup.out 命中、logs/app.log 命中、纯 stdout 未落盘 → 明示「未发现日志文件」
6. QQ/微信等聚合成单行折叠，「隐藏其他」开关生效，且数据不丢
7. fat jar `user-service-1.0.0-SNAPSHOT.jar` 显示为 `user-service`
8. 空闲挂机 1 小时：常驻内存 < 80MB，CPU 平均 < 1%
9. 重启一个 fork 了子进程的 Java 服务：无残留孤儿进程（ps 对照）
10. 在日常开发机（macOS 26）上对照手工 `lsof -i -P -n` + netstat：扫描端口列表无缺失；人为制造 lsof 受限时 UI 出现明示
